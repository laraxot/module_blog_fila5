# BLOG-6.1 — constantTypeCoverage: type declarations reali su 2 costanti

## User story

Come **maintainer del monorepo**, voglio che le costanti pubbliche/private di
`Modules/Blog` abbiano un type declaration reale (PHP 8.3+), così che il bucket
`typeCoverage.constantTypeCoverage` — una percentuale **repo-wide**, visibile
solo con `phpstan analyse Modules` sull'albero intero, non sul singolo modulo —
si avvicini alla soglia 99%+ richiesta dal gate.

## Contesto

Full-tree run del 2026-09-07 (`phpstan analyse Modules --memory-limit=-1
--error-format=json`, prima di questo fix): `typeCoverage.constantTypeCoverage`
165/300 costanti tipizzate = **55.0%**, 135 `file_errors`, uno dei quali su
`Modules/Blog/database/seeders/TagSeeder.php:16`.

Due costanti individuate in questo modulo:

- `app/Http/Livewire/Article/Lists.php:18` — `public const ITEMS_PER_PAGE = 10;`
  (scalare int, nessun type declaration).
- `database/seeders/TagSeeder.php:16` — `private const TAGS = [...]` (lista di
  array associativi `{name: {it,en}, type}`, aveva già un `@var` PHPDoc corretto
  ma nessun type declaration reale sulla `const` stessa).

## Fix

- `Lists.php`: rimosso un `/** @var int */` PHPDoc-only lasciato da un tentativo
  precedente non committato (pattern sbagliato, vedi
  `docs/chat/typecoverage-constant-wrong-var-list-string-regression.md`),
  sostituito con `public const int ITEMS_PER_PAGE = 10;` — nessun PHPDoc
  necessario per uno scalare (stesso pattern verificato su
  `Rating/app/Filament/Blocks/Rating.php`).
- `TagSeeder.php`: aggiunto `array` al type declaration —
  `private const array TAGS = [...]` — mantenendo l'`@var
  list<array{name: array{it: string, en: string}, type: string}>` esistente,
  che descrive correttamente la shape reale (non un `list<string>`).

## Debito preesistente scoperto e risolto in questo pass (blocking, non opzionale)

`Modules/Blog/tests/unit/` e `tests/feature/` (minuscolo) erano duplicati
tracciati in git dei corrispettivi PascalCase `tests/Unit/` e `tests/Feature/`
(pattern noto, skill `psr4-test-filename-pascalcase`). Il duplicato
`tests/unit/SumTest.php` ridichiarava la funzione globale `sum()` già
dichiarata da `tests/Unit/SumTest.php`, causando un **fatal error** che
impediva l'esecuzione di *qualunque* test Pest del modulo — bloccante per il
gate "Pest verde" richiesto da questa story. Verificato con lo script PHP di
detection della skill che ogni file minuscolo aveva un corrispettivo
PascalCase identico prima di rimuovere: `git rm -r --cached tests/unit
tests/feature` + rimozione fisica.

## Debito preesistente NON toccato (fuori scope, documentato)

PHPMD (`tools/phpmd.sh Modules/Blog/app text phpmd.xml`) segnala 9 violazioni
strutturali pre-esistenti, nessuna nei file toccati da questa story:
`LongClassName`, `ExcessiveParameterList` (x2), `MissingImport` (x2),
`UnusedFormalParameter` (x3), `TooManyPublicMethods` (x2). Non meccaniche,
non a basso rischio — richiederebbero refactor di firme pubbliche. Debito
noto, tracciato qui, non silenziato.

Trovate nel working tree, non committate da questa story (fuori scope, non
verificate/testate da questa sessione, lasciate intatte):
`app/Filament/Pages/Dashboard.php` (rename `Filament\Pages\Page` →
`Xot\Filament\Pages\XotBasePage`) e un file non tracciato
`phpmd.ruleset.xml`.

## Learnings

- Non fidarsi di WIP non committato trovato nel working tree: `Lists.php`
  aveva già un tentativo di fix con il pattern sbagliato (`@var` senza type
  reale), e `docs/coverage.md` locale era una versione tronca rispetto a
  HEAD (mancava la sezione Profile::$model già mergiata da un commit
  precedente) — ricostruito da `git show HEAD:docs/coverage.md` invece di
  sovrascrivere.
- Un blocco Pest "fatal" nascosto dietro una directory di test duplicata
  minuscola è invisibile finché non provi a lanciare la suite — PHPStan da
  solo non lo vede.
- Full-tree `phpstan analyse Modules` è costoso e, con molte sessioni
  concorrenti sulla stessa macchina che lanciano lo stesso comando, il
  risultato può arrivare corrotto (`Internal error: Could not read file`)
  per via della cache di risultato condivisa — non ripetere all'infinito,
  documentare la contesa.
